> 챗봇이 말을 이어갈 때 '앞에서 이미 계산해 둔 단어들의 메모'를 노트에 적어 두고 다시 계산하지 않는 절약 기술 (받아쓰기할 때 앞부분을 매번 다시 읽지 않고 요약 노트만 옆에 두는 것)

**대표 논문**: 특정 단일 논문으로 귀속하기 어려운 엔지니어링 기법 — Transformer('Attention Is All You Need', 2017) 이후 자기회귀(autoregressive) 디코딩의 표준 최적화로 정착 (대표 논문 없음, 확인 필요) · **분류**: Attention·시퀀스

## 해결한 문제
GPT 같은 모델은 단어를 하나씩 순서대로 만들기 때문에, 새 단어 하나를 뽑을 때마다 지금까지 나온 문장 전체를 처음부터 다시 계산했다. 그래서 문장이 길어질수록 같은 계산을 몇 번씩 반복하게 되어 생성 속도가 눈에 띄게 느려졌다.

## 핵심 아이디어
비유하면, 긴 회의록을 이어 쓰는 사람이 매 문장마다 회의 처음부터 다시 듣지 않고 '지금까지 핵심 메모'만 책상에 펼쳐 두는 것과 같다. 실제로는 Transformer의 각 attention 층에서 이전 토큰들이 만들어 낸 Key(찾아보기용 색인)와 Value(내용물)를 저장해 둔다. 새 토큰이 들어오면 그 토큰의 Query(질문)와 Key/Value만 새로 계산하고, 저장된 과거 Key/Value와 함께 attention을 한 번만 수행한다. 즉 '과거는 저장, 현재만 계산'으로 바꾸는 것이 전부다.

## 왜 작동하나
원래는 토큰 하나를 추가할 때마다 길이 n짜리 문장 전체를 다시 훑어 n²에 가까운 중복 계산이 생겼는데, 캐시를 쓰면 새 토큰당 계산량이 대략 '현재 길이에 비례'하는 한 번의 attention으로 줄어든다. 같은 결과를 훨씬 적은 연산으로 얻는 셈이라, 긴 대화나 실시간 스트리밍에서 체감 속도 차이가 매우 크다.

## 트레이드오프
- 캐시는 시퀀스 길이 × 층 수 × 헤드 수만큼 커지므로, 문맥이 길어질수록 GPU 메모리를 크게 잡아먹는다.
- 메모리를 아끼려고 배치(batch) 크기를 줄여야 하는 경우가 생겨, 처리량이 오히려 제한될 수 있다.
- 대화 중간 내용을 바꾸거나 지우면 캐시를 무효화·재계산해야 해서 관리 로직이 복잡해진다(캐시 압축·삭제·재사용 정책 필요).

## 계보
**이전**
- 전체 시퀀스를 매번 재계산하는 순진한 자기회귀 디코딩(vanilla autoregressive decoding)

**이후**
- Multi-Query Attention (MQA)
- [[techniques/grouped-query-attention|Grouped-Query Attention (GQA)]]
- Multi-head Latent Attention (MLA)
- PagedAttention / vLLM
- [[techniques/kv-cache|KV cache 양자화·압축]]
- Sliding Window Attention / StreamingLLM

## 피지컬 AI에서의 쓰임
- VLA(비전-언어-행동 모델)가 로봇 팔을 실시간으로 제어할 때, 매 스텝마다 과거 관측·지시 문장을 다시 인코딩하지 않도록 캐시를 재사용해 제어 주기를 맞춘다.
- 로봇과의 장기 대화나 다단계 작업에서 앞선 지시 내용을 캐시로 들고 있어, 매번 전체 대화를 다시 읽지 않고도 맥락을 유지한다.
- 월드모델이나 정책 모델이 미래를 여러 스텝 굴려 보는(rollout) 상황에서, 이미 계산한 상태 표현을 캐시해 반복 추론 비용을 줄인다.

## 💡 아이디어 훅
- 캐시를 '압축된 요약'으로 바꿔 저장하면(예: 저차원 latent로) 긴 문맥에서도 메모리를 아끼면서 성능을 지킬 수 있을까?
- 여러 요청이 같은 시스템 프롬프트나 같은 로봇 지시를 공유할 때, 캐시를 요청 간에 공유(prefix caching)하면 얼마나 빨라질까?
- 로봇의 '작업 기억'을 KV 캐시로 보고, 오래된 항목을 골라 버리는(eviction) 정책을 사람의 망각처럼 설계하면 어떤 장단점이 생길까?
