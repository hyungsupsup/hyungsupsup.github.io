> 문장 속 단어들의 '순서 정보'를 각 단어 벡터를 회전시켜서 심는 방법 — 시계바늘을 위치만큼 돌려놓는 것과 비슷하다.

**대표 논문**: RoFormer: Enhanced Transformer with Rotary Position Embedding (2021) · **분류**: Attention·시퀀스

## 해결한 문제
트랜스포머는 원래 단어 순서를 모른다. 그래서 예전에는 위치마다 고유 번호표(position embedding)를 벡터에 더해줬는데, 이 방식은 학습 때 본 길이보다 긴 문장이 오면 번호표가 낯설어져서 성능이 뚝 떨어졌다. 또 '몇 번째'라는 절대 위치만 알 뿐 '두 단어가 얼마나 떨어져 있나'라는 상대 거리를 자연스럽게 반영하지 못했다.

## 핵심 아이디어
비유하면, 각 단어 벡터를 '그 단어의 위치만큼 시계 방향으로 돌려놓는' 것이다. 실제로는 단어 벡터를 2개씩 짝지어 2차원 평면으로 보고, 위치 값에 비례한 각도로 회전 행렬을 곱한다. 그러면 두 단어의 attention 점수를 계산할 때 회전 각도의 '차이'만 남아서, 결과적으로 두 단어가 얼마나 떨어져 있는지(상대 거리)가 자동으로 반영된다. 위치를 더하는 게 아니라 '돌리는' 방식이라 벡터 크기가 안 변하고, 각도만큼 계속 돌려도 규칙이 유지된다.

## 왜 작동하나
회전은 각도 차이만으로 두 벡터의 관계가 결정되기 때문에, 절대 위치를 외우는 대신 상대 거리를 자연스럽게 표현한다. 덕분에 학습 때보다 긴 문장이 와도 '거리' 개념이 그대로 이어져 길이 일반화(extrapolation)가 잘 된다. 또 벡터에 값을 더하지 않아 원래 단어 정보가 덜 훼손되고, 구현도 곱셈 몇 번이라 계산 부담이 거의 없다.

## 트레이드오프
- 학습 때 본 길이를 크게 넘어서면 여전히 성능이 흔들려서, 실전에서는 위치 스케일을 조정하는 별도 트릭(NTK scaling 등)이 필요할 때가 많다.
- 회전 각도를 정하는 '기저 주파수' 설정에 따라 긴 문맥 성능이 민감하게 달라져서 튜닝이 까다롭다.
- 위치 정보를 회전으로 섞기 때문에, 아주 특수한 구조(일부 커스텀 attention)에 끼워 넣을 때 호환을 맞추기 번거롭다.

## 계보
**이전**
- Absolute Position Embedding (학습형 위치 벡터)
- Sinusoidal Position Encoding (사인·코사인 절대 위치 인코딩)
- Relative Position Encoding (상대 위치 편향)

**이후**
- ALiBi (Attention with Linear Biases)
- YaRN (긴 문맥용 RoPE 스케일링)
- NTK-aware RoPE scaling
- LongRoPE

## 피지컬 AI에서의 쓰임
- VLA(로봇이 언어 지시를 보고 행동하는 모델)에서 긴 조작 이력·센서 시퀀스를 다룰 때 위치 정보를 안정적으로 유지하는 데 쓰인다.
- 월드모델·비디오 예측 모델에서 프레임 순서와 시간 간격을 표현해 '몇 스텝 뒤'를 일관되게 예측하도록 돕는다.
- LLM 기반 로봇 플래너가 긴 대화·관측 로그를 처리할 때 문맥 길이를 늘리는 핵심 부품으로 들어간다.

## 💡 아이디어 훅
- 로봇 팔의 '관절 각도'를 위치 대신 회전으로 인코딩하면 시퀀스 길이 일반화에 도움이 될까?
- RoPE의 '상대 거리만 남기는' 성질을 시간 간격이 불규칙한 센서 데이터에 어떻게 응용할 수 있을까?
- 회전 각도(주파수)를 학습 가능하게 만들면 긴 문맥과 짧은 문맥을 동시에 잘 다룰 수 있지 않을까?
