> 거대 모델의 몸통은 얼려두고, 옆에 얇은 '덧대기 판' 두 장만 붙여 학습하는 초경량 미세조정 기법 — 두꺼운 사전에 포스트잇만 붙이는 셈.

**대표 논문**: LoRA: Low-Rank Adaptation of Large Language Models (2021, ICLR 2022) · **분류**: 효율화·적응

## 해결한 문제
예전에는 모델을 새 작업에 맞추려면 모든 가중치(수십억 개의 숫자)를 다시 학습하는 전체 미세조정(full fine-tuning)을 해야 했다. 그러면 GPU 메모리가 몇 배로 들고, 작업마다 모델 사본을 통째로 저장해야 해서 보관 비용이 폭발한다. Adapter나 prefix tuning 같은 대안도 있었지만, 추론할 때 층 사이에 추가 계산이 끼어들어 속도가 느려지는 문제가 있었다.

## 핵심 아이디어
비유하면, 두꺼운 백과사전(원본 가중치)은 손대지 않고 옆에 얇은 메모지 두 장(A와 B)만 끼워 넣어 '이번 작업에서는 이렇게 읽어라'는 보정을 더하는 방식이다. 실제로는 각 층의 큰 행렬 W 옆에 아주 작은 두 행렬 A(입력→r차원)와 B(r차원→출력)를 나란히 두고, 출력을 W·x + B·A·x로 계산한다. 여기서 r(랭크)은 8~64 정도의 아주 작은 숫자라서, 학습하는 파라미터 수가 원본의 1% 미만으로 줄어든다. B는 0으로 초기화해서 학습 시작 시점에는 원본 모델과 완전히 똑같이 동작하고, 학습이 끝나면 B·A를 W에 그냥 더해버릴 수 있어서 추론 속도 손해가 전혀 없다.

## 왜 작동하나
핵심 관찰은 '큰 모델을 새 작업에 맞출 때 실제로 필요한 변화량은 생각보다 훨씬 낮은 차원에 몰려 있다'는 것이다. 즉 수십억 개를 다 고칠 필요 없이, 몇 개의 방향(랭크 r)만 조정해도 충분히 원하는 적응이 된다. 덕분에 옵티마이저 상태·기울기 저장 부담이 확 줄어 작은 GPU로도 학습되고, 학습 후에는 가중치에 합쳐버릴 수 있어서 배포 시 추가 지연이 없다.

## 트레이드오프
- 랭크 r을 너무 작게 잡으면 복잡한 새 작업(예: 완전히 다른 언어나 도메인)에 적응이 부족하고, 너무 크게 잡으면 메모리 이점이 줄어든다.
- 원본과 크게 다른 분포를 배우는 지속 사전학습(continual pretraining)에는 전체 미세조정보다 약할 수 있다.
- 작업별 LoRA를 여러 개 동시에 서빙하려면 어댑터 교체·배치 처리를 따로 관리해야 해서 시스템이 복잡해진다.

## 피지컬 AI에서의 쓰임
- VLA(비전-언어-행동 모델)를 로봇 팔 데이터로 적응시킬 때, OpenVLA 같은 모델을 LoRA로 소규모 로봇 데이터에 맞춰 학습하는 식으로 쓰인다.
- diffusion policy나 월드모델의 UNet/DiT에 LoRA를 붙여, 새 작업·새 물체에 대한 행동 생성만 가볍게 조정한다.
- LLM 에이전트에서 고객별·도메인별 '스킬 카트리지'처럼 LoRA를 갈아 끼워, 하나의 베이스 모델로 여러 로봇 태스크를 서빙한다.

## 💡 아이디어 훅
- LoRA를 강화학습(RLHF/RLVR) 파인튜닝에 쓸 때, 랭크를 키우는 것과 학습률을 키우는 것 중 무엇이 더 효과적일까?
- 로봇이 현장에서 계속 배우는 온디바이스 지속학습에 LoRA를 쓴다면, 어댑터를 언제 합치고 언제 따로 보관해야 할까?
- 여러 LoRA를 가중치 공간에서 평균·합성하면 새로운 스킬 조합이 생길까, 아니면 서로 간섭할까?
